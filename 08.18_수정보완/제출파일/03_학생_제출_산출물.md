|---|---|
| 결함 ID | BUG-01 |
| 선택자 | `.con` (또는 `layout_cpn.css`) |
| 문제 선언 | `max-width: var(--containner);` |
| 화면 증상 | 1920px 등 와이드 화면에서 `.con` 영역의 최대 너비(1600px) 제한이 풀려 화면 전체로 늘어나며, 좌우 여백 및 중앙 정렬 레이아웃이 깨짐 |

## 6. 최종 회고

- 가장 찾기 어려웠던 오류와 이유: 결함 1(`--containner` 변수명 오타)과 결함 3(`body`의 `min-width: 1600px`). 변수명 오타는 브라우저 콘솔에 에러로 표시되지 않아 레이아웃 계산값(Computed)과 토큰 선언부를 대조해야 했고, body의 고정 너비는 미디어 쿼리가 적용되어도 최상위 컨테이너로 인해 전체 스크롤바가 남는 원인을 파악하는 데 세밀한 분석이 필요했다.
- CSS 파일 분리 기준을 정한 방법: 과제안내서의 기준에 맞추어 기본 리셋/폰트(`normal.css`), 원시 디자인 토큰(`root.css`), 의미 기반 디자인 토큰(`component.css`), 버튼 및 제어 UI(`btn_cpn.css`), 개별 컴포넌트/유틸(`item_cpn.css`), 공통 레이아웃/그리드(`layout_cpn.css`), 페이지별 스타일(`style.css`), 반응형 미디어 쿼리(`media.css`) 순으로 역할과 우선순위(캐스케이딩)에 맞추어 분리했다.
- 파일 분리 후 캐스케이드 문제를 예방한 방법: 일반적이고 낮은 특이성의 리셋/토큰 스타일을 상단에 배치하고, 컴포넌트와 레이아웃을 거쳐 구체적인 페이지 스타일과 반응형 미디어 쿼리를 최하단에 배치하여 스타일 덮어쓰기 순서(Cascade order) 충돌을 방지했다.
- 다시 수행한다면 개선할 점: 초기 분리 단계부터 브라우저 개발자 도구의 Styles와 Computed 탭을 적극 활용해 CSS 변수 유효성과 고정 너비 속성을 초기에 체계적으로 진단하여 디버깅 시간을 단축하겠다.
